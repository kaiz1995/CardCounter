# 够级浮窗 UI 规格（参考图版）

## 1. 目标与口径

- 视觉结构按用户参考图：五个对手计牌框、底部外面剩余框、圆形隐藏/重置按钮。
- 五个对手框显示该座位**累计出过的牌**；末列显示该玩家剩余手牌总数。
- 底部框显示：`外面剩余 = 198张初始库存 - 自己锁定手牌 - 五个对手累计出牌`。
- 自己出牌不再扣外面剩余。当前“只保存外面合计、不保存玩家身份”的旧约束由本需求替代。
- 不增加设置页、拖拽、换肤、逐局历史入口。

## 2. 统一坐标系

设计基准：横屏游戏画布 `1280 × 578`。

运行时：

```text
sx = 实际画布宽 / 1280
sy = 实际画布高 / 578
实际矩形 = (x*sx, y*sy, w*sx, h*sy)
```

必须跟随**游戏画布**缩放；存在黑边时先加画布 `offsetX/offsetY`，不能直接按整屏缩放。以下均为画布内坐标。

## 4. 框内结构

### 4.1 Rank 顺序

所有框固定：

```text
大 小 2 A K Q J 10 9 8 7 6 5 4 3
```

不得按牌量重排；花色不显示。

### 4.2 五个对手框

- 两行、16列；前15列 Rank，末列为 `剩`。
- 首行高 `25`：Rank/`剩`；次行高 `27`：累计出牌数/剩余手牌数。
- 前15列等分可用宽度，末列宽 `27`；允许 `10` 字号缩小，不改单元格宽度。
- 累计出牌初值为 `0`；玩家剩余初值 `33`。
- `玩家剩余 = 33 - 该座位累计出牌总数`。结果越界立即停记，不夹成0继续显示。

### 4.3 底部外面剩余框

- 两行、15列，无“剩”末列。
- 每列等宽约 `35`；首行高 `36`，次行高 `40`。
- 首行 Rank，次行对应 `outsideRemaining[rank]`。
- 未锁定自己手牌：数值显示 `—`；停记：冻结最后可信值，框外描边改红。

## 5. 视觉样式

- 外框：`#090A0B`，2px 描边，圆角 12px。
- 单元格底色：首行 `#3B3E40`，次行 `#35383A`。
- 分隔线：`#181A1C`，1px。
- Rank/`剩`：`#F5F5F5`，加粗，居中；对手框 15px，底框 22px。
- 对手累计值：0 用 `#6F7275`；大于0用 `#FF334A`，对手框 16px。
- 玩家“剩”和底部所有剩余值：`#FF334A`，加粗；底框 23px。
- 字体：系统无衬线压缩优先；数字可轻微斜体，禁止引入字体依赖。
- 整框透明度约94%；不加阴影、动画、渐变。
- 隐藏/重置：淡黄 `#FFE59A` 实心圆，3px `#232323` 描边，黑字 22px；文字分别为“隐藏”“重置”。

## 6. 交互

- 计牌框只读、完全穿透触摸。
- 点“隐藏”：隐藏六个框和重置按钮；原按钮原位保留，文字变“显示”。再次点恢复。
- “重置”采用 `800ms` 长按：清空本局事件、玩家累计、外面剩余基线，回到等待锁定手牌；短点不执行，防误触。
- 仅在 `StablePlayGate` 接受事件后刷新数字；识别候选帧不得驱动 UI 闪烁。
- `PAUSED`：冻结可信数据、六框红色描边；不以猜测结果更新。

## 7. WindowManager 最小组织

只用3个 Window：

1. `CounterOverlayView`：全画布透明自绘层，一次绘制五个对手框和底部框；`FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCHABLE | FLAG_LAYOUT_IN_SCREEN`。
2. `HideControlView`：仅覆盖隐藏按钮矩形；可触摸、不可聚焦、`FLAG_NOT_TOUCH_MODAL`。
3. `ResetControlView`：仅覆盖重置按钮矩形；可触摸、不可聚焦、`FLAG_NOT_TOUCH_MODAL`。

不用一个可触摸的全屏根窗口，否则透明区域也可能挡住游戏操作；不用7/8个独立展示窗口，避免同步与生命周期复杂度。

屏幕旋转、分辨率或画布偏移改变时，只更新3个 Window 的布局。所有 UI 更新在主线程；绘制数据使用不可变快照。

## 8. 与识别链隔离

MediaProjection 会采到浮窗，必须遵守：

- 五个对手框位于牌面 Rank 识别带下方；YOLO/模板只裁牌面区域，不裁计牌框。
- `LEFT_TOP/RIGHT_TOP` 可见性采样下边界截到 `y=150`，不要进入 `y=154` 开始的计牌框。
- 左下/右下公开牌采样下边界不得超过 `y=318`。
- 手牌识别 ROI 下边界不得超过 `y=486`；底部框从 `y=495` 开始，保留9px安全间隔。
- 对所有推理输入增加固定 overlay exclusion rectangles（上述7个矩形外扩4px）；若未来 ROI 改动，交集必须在测试中失败，不能静默覆盖。
- UI 只能消费已接受识别结果，不能反向成为检测候选，避免“浮窗数字识别浮窗数字”的反馈环。

## 9. 数据最小改动要求

当前 `OutsideCardsPlayed` 没有座位信息，无法还原五个玩家。实现时必须让已接受事件携带 `PlayZone`（排除 `SELF`）：

```text
playedByZone[zone] += cards
outsidePlayed = sum(playedByZone)
outsideRemaining = initialInventory - selfLockedHand - outsidePlayed
```

旧会话没有 zone，不能猜分配；版本升级后自动开新局一次。五框显示 `playedByZone`，底框继续显示派生的 `outsideRemaining`。

## 10. 验收

- 1280×578 截图中，各框与本文件坐标误差不超过2px。
- 五个对手分别出牌后，只更新对应座位框；底部外面剩余同步减少。
- 自己出牌不减少底部外面剩余。
- 重复稳定帧不重复累计；同牌组清空后再次出现可再次累计。
- 浮窗显示/隐藏均不改变同一帧牌面的识别结果。
- 透明区域触摸全部落到游戏；只有隐藏、重置圆钮截获触摸。
- 重启服务后当前局可回放；旧无座位会话不伪造玩家数据。
