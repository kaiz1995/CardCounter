# 够级记牌器：YOLO 与逐座位显示实施计划

## 已确认的现状

- 当前库存公式已稳定：`外面剩余 = 固定初始库存 - 自己锁定手牌 - 五名对手累计出牌`。
- `PlayZone` 已区分顶部、左上、左下、右上、右下、自己六区，并有稳定/清空/重复布防门。
- 现有 `OutsideCardsPlayed` 仅保存牌组，不保存座位；要显示五名对手各自累计出牌，座位必须进入事件日志并由归约器派生状态。
- `SessionStore` 直接保存事件 JSON；事件结构变化必须设计旧日志兼容策略。
- 当前浮窗只有一个左上横条；目标改为截图布局：五个对手框各显示 15 个 Rank 累计出牌和右侧累计总张数，底部显示 15 个 Rank 的外面剩余。
- YOLO11 只替换牌面识别层；现有 MediaProjection、六区、稳定门、事件重放、库存公式继续复用。

## 目标定义

1. 保持全局公式：`外面剩余 = 198 - 自己锁定手牌 - 五名对手累计出牌`。
2. 五个固定对手座位分别累计15种 Rank 的正式出牌，自己出牌不扣外面剩余。
3. 浮窗按 `overlay-reference-ui-spec.md` 绘制五个座位框、底部外面剩余框、隐藏和重置按钮。
4. YOLO11 以 TFLite CPU 建立正确性基线，再以真机实测选择MNN后端；识别不确定时 RETRY/PAUSE。

## 实施顺序

### 1. 逐座位领域账本

- `OutsideCardsPlayed` 增加可选座位；新事件必须携带座位。
- `GameState` 增加五座位累计，`outsidePlayed` 仍为权威合计。
- 归约、撤销、重放同时维护合计与座位账本。
- 旧 JSON 没有座位时只保留合计，不猜座位；进入新版逐座位模式时开新局。
- 单测覆盖独立累计、合计公式、撤销、旧日志兼容。

### 2. 参考图浮窗

- 按 `overlay-reference-ui-spec.md` 使用一个只读全画布绘制 Window 和两个小控制 Window。
- 五框显示各座位累计出牌；右列显示 `33 - 累计正式出牌张数`。
- 底部显示 `outsideRemaining`；PAUSED 冻结可信数据并红框。
- 固定排除矩形进入识别预处理，避免浮窗反向被识别。

### 3. YOLO11 P0/P1

- 已解密 MNN/TFLite 320 模型 SHA-256 必须匹配原清单。
- 建立28检测类到15 Rank映射，运行时读取输入/输出张量形状。
- TFLite CPU先跑现有9局手牌和G3/G4公开牌帧，只输出诊断。
- 达到现有9/9手牌基线后才允许驱动事件。

### 4. MNN与切换

- TFLite正确后接MNN；相同输入必须得到等价 Rank 结果。
- BRA-AL00的OpenCL被系统链接器隔离，使用MNN CPU；TFLite保留兜底。
- 单飞、latest-frame-wins，不允许推理任务排队或阻塞采集线程。

### 5. 完整验收

- 五座位分别出牌只更新对应框，全局剩余同步减少。
- 自己出牌不改变全局剩余。
- 验收素材内错误扣牌0、重复扣牌0、漏记0。
- 同牌清空后再次出现可重新累计；未知、跨区、遮挡必须PAUSE而非猜测。
- `test assembleDebug`通过，并在Mate 60连续运行10分钟无任务堆积或内存持续上涨。
