## 1. 固定规则与变化因素

### 1.1 固定规则

| 项目 | 结论 |
|---|---|
| 游戏 | 多乐够级 |
| 玩家 | 6 人 |
| 扑克牌 | 4 副，共 198 张 |
| 初始发牌 | 每人先发 33 张 |
| 固定裁牌 | 去掉 10 张 3、8 张 4 |
| 买牌来源 | 买 3、买 4只在这 198 张内部转移，不新增、不移除牌 |
| 花色 | 不统计，只识别 Rank |
| 运行方式 | 自动识别、自动扣减 |
| 人工确认 | 不弹确认窗口 |
| 手工记牌 | 不支持点击 Rank 加减 |
| UI | 只显示一个横向统计条 |

### 1.2 手牌数量不是固定状态

发牌后可能发生：

- 交贡
- 还贡
- 买 3
- 买 4
- 其他牌权转移

因此：

- “每人 33 张”只描述初始发牌。
- 正式开局时，每个人实际持牌数可能不等于 33。
- 不建立“每名玩家固定从 33 张开始递减”的模型。
- 不记录某名玩家出了哪些牌。
- 不显示五名玩家独立统计条。

### 1.3 198 张 Rank 初始库存

| Rank | 初始数量 |
|---|---:|
| 大王 | 4 |
| 小王 | 4 |
| 2、A、K、Q、J、10、9、8、7、6、5 | 各 16 |
| 4 | 8 |
| 3 | 6 |
| 合计 | 198 |

首版只支持该固定规则，不设计任意副数和删牌配置。

已确认：3 固定共 6 张，4 固定共 8 张；交贡、还贡、买牌只改变持牌归属，不改变 198 张总库存和各 Rank 总库存。

## 2. 唯一统计目标

软件只回答一个问题：

> 扣除自己正式开局时持有的牌，再扣除外面累计公开打出的牌，各 Rank 在外面还剩多少？

### 2.1 核心公式

```text
外面剩余[Rank]
= 该 Rank 固定初始数量
- 自己锁定持牌[Rank]
- 外面累计已出[Rank]
```

“外面累计已出”只统计另外五名玩家公开打出的牌，不包含自己打出的牌。

### 2.2 示例

4 副牌中 A 初始共 16 张：

```text
自己锁定持有 A = 3
外面累计已出 A = 8

外面剩余 A = 16 - 3 - 8 = 5
```

横条显示：

```text
A  5
```

### 2.3 自己出牌不重复扣减

自己的牌已经在“自己锁定持牌”中一次性扣除。

自己后来打出 A，不改变“外面剩余 A”。否则同一张牌会被扣两次。

### 2.4 总数不是固定 165

初始发牌时自己有 33 张，但交贡、还贡、买 3、买 4 后，自己正式开局持牌数可能变化。

因此初始化后：

```text
外面剩余总数 = 198 - 自己锁定持牌总数
```

不能固定写成 165。

## 3. 统计边界

### 3.1 记录

- 自己正式开局时各 Rank 持有数量。
- 外面累计公开打出的各 Rank 数量。
- 各 Rank 当前外面剩余数量。
- 已接受的外面出牌事件。
- 撤销记录和会话健康状态。

### 3.2 不记录

- 某个玩家出了什么。
- 某个玩家还剩多少张。
- 玩家座位、阵营、对门关系。
- 过牌历史。
- 玩家个人 Rank 统计。
- 每个人是否仍为 33 张。
- 某个对手手中具体持有哪些牌。

### 3.3 仍需区分自己与外面

不追踪五名对手身份，但必须把出牌事件分成两类：

| 出牌来源 | 是否扣“外面剩余” |
|---|---|
| 自己 | 否 |
| 另外五人中的任意一人 | 是 |

因此只需要二分类：`SELF / OUTSIDE`，不需要识别具体是哪名对手。

## 4. 单横条界面

参考图片只借鉴横向灰色统计条形式；不借鉴其六副牌数据、逐玩家统计或实现方式。

### 4.1 主界面

```text
┌────────────────────────────────────────────────────────────────────┐
│ 大  小  2   A   K   Q   J  10   9   8   7   6   5   4   3 │
│ 4   3  10   5  12  14  13   9  11  10  12  13  14   5   4 │
└────────────────────────────────────────────────────────────────────┘
```

每格只显示当前“外面剩余”数量。

### 4.2 布局

- 横屏单行，固定在左上安全区。
- 不遮挡六个出牌展示区和自己的手牌 Rank。
- 横条最终尺寸和左上偏移必须在六区标定后锁定；若与顶部展示区冲突，只能缩小单行单元，不能压住识别区或改为多行。
- 透明灰底、细边框、高对比数字。
- 正常模式不支持拖动，避免进入识别 ROI。
- 可一键收起为小图标。

### 4.3 控制

横条只保留小型控制：

- 收起/展开
- 新局重置
- 撤销最后一次自动扣减
- 调试状态开关

不提供：

- Rank 点击扣减
- Rank 长按恢复
- 逐玩家展开
- 识别确认弹窗

### 4.4 非阻塞状态

| 状态 | 标记 | 行为 |
|---|---|---|
| 正在识别自己持牌 | 灰色 | 不显示正式剩余数 |
| 正常运行 | 绿色 | 自动更新横条 |
| 正在重试 | 黄色 | 暂缓本次扣减 |
| 状态不可靠 | 红色 | 停止自动扣减 |

## 6. 自己持牌初始化

### 6.1 初始化目标

识别的不是“刚发完牌时固定 33 张”，而是：

> 贡牌、还贡、买 3、买 4等操作结束后，自己进入正式出牌阶段时实际持有的全部牌。

该快照命名为 `SelfLockedHand`。

### 6.2 初始化过程

```text
检测发牌完成
    ↓
持续观察自己的手牌区
    ↓
贡牌/还贡/买牌导致手牌变化 → 更新候选快照
    ↓
每次稳定后保存 lastStablePrePlayHand
    ↓
检测到第一项正式出牌动作开始
    ↓
锁定动作发生前的 lastStablePrePlayHand
    ↓
计算外面初始剩余 = 198 - SelfLockedHand
```

### 6.3 不再使用“必须等于33”门禁

由于正式开始时手牌数量可能变化，不能要求识别结果等于 33。

改用以下校验：

1. 识别出的总张数与游戏界面显示的自己手牌总数一致；如果界面没有数字，使用多帧牌位一致性。
2. 游戏不显示自己手牌总数时，必须从牌位锚点和可见牌边缘独立得到相同张数。
3. 每个 Rank 数量不得超过固定初始库存。
4. 连续多帧的牌位数和 Rank 多重集合一致。
5. 所有牌位都有明确 Rank，不用默认值补齐。
6. `198 - 自己锁定持牌总数` 必须大于等于 0。

`lastStablePrePlayHand` 必须携带采样时间和画面稳定区间。第一项正式动作发生后禁止使用动作后的手牌帧覆盖它。

### 6.3.1 首段实录的初步结论

已审查 22 秒目标游戏横屏录屏：

- 开局画面中的底部手牌区，约 33 张重叠牌均露出可读 Rank 角标，牌列边缘也可用于独立计数。
- 因此“Rank 锚点 + 牌边缘”双计数路线在该界面上**初步可行**。
- 后续已以现有 9 段开局验证首出前候选更新和首出锁定；9/9 Rank 向量及边界通过。无需每段分别覆盖交贡、还贡、买 3、买 4。

### 6.4 锁定后禁止随自己出牌重算

`SelfLockedHand` 是统计基线，不是自己当前手牌。

正式出牌后，自己的手牌会自然减少，但基线不能随之减少。否则“外面剩余”会错误增加。

### 6.5 开局后仍发生牌权交换

已确认：交贡、还贡、买 3、买 4均发生在第一项正式出牌动作前。系统只在锁定前持续更新候选快照。

若运行中意外检测到新的牌权交换阶段，立即进入 PAUSE，并保留最近帧供诊断；不替换 `SelfLockedHand`。

## 7. SELF / OUTSIDE 判断

不需要识别具体对手，但必须可靠判断稳定公开牌组落在哪一类展示区。

### 7.1 必需证据

- 画面按目标游戏坐标标定六个固定出牌展示区：底部自身区 + 五个对手区。
- 同一展示区内公开牌组出现并稳定，且 Rank 可完整识别。
- 稳定牌组落入底部自身区，为 SELF 的主证据；落入任一对手区，为 OUTSIDE 的主证据。
- “提示 / 出牌”、头像高亮、倒计时只作为交叉校验；过牌提示只作为非出牌过滤证据。

游戏不会在自己出牌后立即减少手牌，因此手牌区域变化不参与 SELF 判定。

### 7.2 决策规则

```text
自身展示区中的正式出牌牌组稳定 → SELF → 不扣外面剩余
任一对手展示区中的正式出牌牌组稳定 → OUTSIDE → 扣外面剩余
牌组落在未知区域，或正式出牌类型不明确 → RETRY
来源不明确 → RETRY
事件已经错过仍无法判断 → PAUSE
```

不需要知道 OUTSIDE 是五人中的哪一个。

### 7.2.1 禁止反证推断

“没有看到自己的控件”不等于 OUTSIDE；“看到了牌”也不等于正式出牌。

牌组不在已标定对手展示区，或无法确认该牌组属于正式出牌时，必须 RETRY 或 PAUSE；不能以“不是自己”反推出“必为外面”。这是避免漏看自身控件、误扣外面库存的硬门禁。

### 7.3 过牌

过牌不改变总牌数，也不需要记录。

只有当过牌提示有助于判断下一次是否为 SELF 时，才作为临时观察信号；不进入长期状态。

### 7.4 首段实录对行动归因的结论

- 自己的五张公开牌稳定显示在底部手牌上方；右下对手的两张公开牌稳定显示在该头像左上方。
- 因此“六个出牌展示区”升级为 G4 候选主路线；其优先级高于行动高亮和控件文本。
- 自己操作阶段可见“提示 / 出牌”控件，保留为 SELF 交叉校验。
- 对手过牌可见“过牌 / 不要”等座位附近提示；它们只表示非出牌动作，绝不能扣库存。
- 尚未证明所有六区在各种牌型、动画和“开点”等动作下均稳定。因此 G4 未关闭；需要逐帧标注“展示区牌组 → 正式出牌类型 → Rank”的对应关系。

## 8. 六区出牌展示状态机

### 8.1 ActionBoundaryDetector

系统不保存玩家身份，但必须瞬时观察六个固定出牌展示区的牌组进入、稳定、变化和消失。

每个展示区发生可靠牌组变化时，生成递增的 `actionEpoch`。该值只用于定义视觉事件边界，不进入玩家统计。

```text
运行时事件键 = actionEpoch + 展示区类别 + 稳定牌面摘要
```

作用：

- 两名玩家连续打出完全相同牌面时，仍生成两个事件。
- 上一展示区牌组未清空，但另一区出现新牌组时，可以重新布防。
- 已检测到展示区变化却没有生成完整事件时，触发完整性异常。

行动边界检测必须保留六个展示区和控件 ROI 的短时前后帧环形缓冲。提示文字若比牌组早出现或晚消失，仍可与同一 `actionEpoch` 交叉校验；环形缓冲只用于当前事件判定，不形成玩家历史。

### 8.1.1 六区坐标与边界

六区名称只描述屏幕几何位置，不代表、也不持久化任何玩家身份：

    TOP
    LEFT_UP / RIGHT_UP
    LEFT_DOWN / RIGHT_DOWN
    SELF

每局开始按以下步骤标定：

1. 先裁出游戏画布，去掉状态栏、导航栏和系统黑边。
2. 以画布宽高归一化到 `[0,1] × [0,1]`；配置中禁止写死原始像素。
3. 用六个固定头像位置作为视觉锚点，向牌桌内侧定义各自的候选展示区：TOP 向下、SELF 向上、左侧向右、右侧向左。
4. 每个候选区再向内收缩为“接受安全区”；六个接受安全区不得重叠，也不得覆盖自己手牌区、系统控件区或左上横条。

牌组归属规则：

- 所有 Rank 锚点和可见牌边缘都落入同一个接受安全区，才分配该区。
- 牌组跨越两个区、落在区外、或被横条遮挡，归为 UNKNOWN。
- UNKNOWN 不作最近邻、方向或轮次猜测；RETRY 后仍不能唯一归属则 PAUSE。

`TOP / LEFT_UP / LEFT_DOWN / RIGHT_UP / RIGHT_DOWN / SELF` 只保留在当前帧处理和短时环形缓冲中。已接受事件日志只保存 `SELF / OUTSIDE`，不保存区名。

### 8.2 PlayZoneStateMachine

```text
EMPTY
  ↓ 检测牌面进入
APPEARING
  ↓ 连续帧趋于稳定
STABLE
  ↓ Rank 与 SELF/OUTSIDE 均明确
CONSUMED
  ↓ 本展示区清空或明确出现下一次新牌面
EMPTY
```

规则：

- 同一 `actionEpoch` 内，每个稳定牌面最多生成一次事件。
- 展示区必须先经历“空/旧牌面 → 新牌组出现 → 稳定”的变化；长期停留的旧牌组不得在下一帧再次计数。
- Hash 只辅助帧比较，不单独定义事件。
- 连续两次完全相同牌面由不同 `actionEpoch` 区分。
- 牌数相同但 Rank 改变属于新事件。
- 动画中间帧不能扣牌。
- 一次出牌允许包含多个 Rank。
- SELF 事件识别后标记已消费，但不扣外面库存。
- OUTSIDE 事件识别后才更新横条。
- “查点 / 不查点”“提示 / 出牌”等本地控件、座位旁“过牌 / 不要”等提示必须先由 UI 控件过滤器排除，不能被展示区牌面分类器当作扑克牌或新牌局边界。

### 8.3 ObservationCompletenessGuard

每个可疑出牌观察必须闭环成以下结果之一：

- 已接受的 SELF 事件。
- 已接受的 OUTSIDE 事件。
- 当前六区标定版本和运行时 `zoneEpoch`（短时、不可作为玩家历史）。
- 已证明为动画、聊天等非出牌变化。
- 明确失败并进入 PAUSE。

触发 PAUSE：

- 任一展示区出现牌形变化，但窗口结束后没有对应事件。
- `actionEpoch` 已切换，但上一动作仍无结论。
- 牌面从出现到消失，始终无法得到稳定 Rank。
- SELF/OUTSIDE 来源始终不明确。

如果游戏界面可稳定读取五名对手的当前手牌总数，可以只读取其合计作为旁路校验；不保存逐玩家历史。旁路合计与横条总剩不一致时立即 PAUSE。

### 8.4 可见牌组的语义门禁

可见牌组先归类，再决定是否影响库存：

| 类型 | 含义 | 是否扣 OutsidePlayed |
|---|---|---|
| FORMAL_PLAY | 普通出牌或开点；牌会离开出牌者手牌 | 仅 OUTSIDE 扣减 |
| PRE_PLAY_TRANSFER | 交贡、还贡、买牌等开局转移 | 不扣；只影响锁定前候选手牌 |
| DISPLAY_ONLY | 过牌提示、动画或其他未确认展示 | 不扣 |
| UNKNOWN | 无法判定类型 | PAUSE |

已确认：“开点”会让牌离开出牌者手牌，因此归为 FORMAL_PLAY。其他未确认的特殊展示仍不得按文字或卡片外观猜测语义。

已确认：正式阶段除普通出牌、开点外，没有其他会让牌真正离开手牌的特殊动作。因此首版语义表只接受这两类正式出牌。

## 9. Rank 分割与识别

### 9.1 识别对象

- 自己手牌区：每张重叠牌可见的 Rank 角标。
- 中央出牌区：每张公开牌可见的 Rank 角标。
- 不识别花色。

### 9.2 分割

- 使用固定大 ROI，不使用完整卡牌轮廓检测。
- 通过 Rank 锚点响应和牌边缘间距定位牌位。
- 支持多排手牌、重叠牌、不同暴露宽度。
- 自己手牌与中央出牌使用不同布局参数。
- 不假设固定等宽网格或固定出牌张数。
- 目标实录中底部约 33 张重叠手牌的 Rank 角标可见；G2 仍须以原始分辨率和多种布局重新量化验证。

### 9.3 分类

- 模板匹配为主。
- 模板集来自目标游戏、目标手机实际截图。
- 自己手牌和中央牌面分别标定尺寸。
- OCR 只作为独立辅助证据。
- 模板与 OCR 冲突时 RETRY，不比较原始分数强行选一个。
- 阈值由真实录屏验证集确定。

### 9.4 多帧融合

只有以下结果连续稳定才输出：

- 牌位数量
- 每个牌位位置
- Rank 多重集合
- SELF/OUTSIDE 来源

## 10. 状态模型

### 10.1 最小状态

| 状态 | 含义 |
|---|---|
| `InitialInventory[15]` | 固定 198 张 Rank 库存 |
| `SelfLockedHand[15]` | 正式开局时自己被排除的牌 |
| `OutsidePlayed[15]` | 外面累计公开打出的牌 |
| `OutsideRemaining[15]` | 横条显示值 |
| `SessionHealth` | 初始化中、正常、重试、暂停 |
| `EventLog` | 已接受的状态事件 |

派生关系：

```text
OutsideRemaining[i]
= InitialInventory[i]
- SelfLockedHand[i]
- OutsidePlayed[i]
```

### 10.2 事件类型

| 事件 | 是否影响横条 |
|---|---|
| `NewGame` | 重置全部状态 |
| `SelfHandLocked` | 初始化所有 Rank |
| `OutsideCardsPlayed` | 扣除对应 Rank |
| `SelfCardsPlayed` | 不扣，只用于事件去重和诊断 |
| `Reverted` | 反向撤销指定事件 |
| `SessionPaused` | 停止自动扣减 |

不保存玩家 ID、座位和团队。

### 10.3 唯一事实源

- 事件日志是唯一事实源。
- 横条状态可由事件重放得到。
- 撤销使用 `Reverted` 事件，不维护第二套可漂移的 UndoStack。
- 持久化恢复后必须重新归约并校验。

### 10.4 不变量

1. `InitialInventory` 总数恒等于 198。
2. 任一 Rank 的 `SelfLockedHand` 不超过其初始数量。
3. 任一 Rank 的 `OutsidePlayed` 不得为负。
4. 任一 Rank 的 `OutsideRemaining` 不得为负。
5. `Initial = SelfLockedHand + OutsidePlayed + OutsideRemaining`，逐 Rank 成立。
6. SELF 出牌事件不得改变 `OutsideRemaining`。
7. 同一个中央出牌事件不得重复应用。
8. 重放事件日志必须得到完全相同的横条。
9. 每个已结束的 `actionEpoch` 必须有明确观察结论。

## 11. 无确认自动策略

| 决策 | 行为 |
|---|---|
| ACCEPT | Rank 和来源均稳定，应用事件 |
| RETRY | 保留短时帧，继续识别，不更新横条 |
| PAUSE | 关键事件无法恢复，标红并停止扣牌 |

禁止：

- 弹出人工确认框
- 来源不清时默认当作 OUTSIDE
- 低置信结果超时后强制扣牌
- 模板/OCR 冲突时取高分
- 状态已经不可靠却继续显示绿色正常

### 11.1 PAUSE 为本局终态

PAUSE 表示已经发生无法可靠补回的统计断点，不是普通网络重试。

- RETRY 只在当前事件的短时帧环形缓冲内执行；事件窗口结束仍无结论，升级为 PAUSE。
- ACTIVE 进入 PAUSED 后，本局不再接受任何新的自动事件，也不提供“继续本局自动记”。
- 红色横条显示“本局停记”，调试状态可附简短原因码：基线失败、区位不唯一、Rank 不稳定、未知语义、新局不明、截屏中断。
- 用户可收起、查看调试、撤销最后一次已接受 OUTSIDE 事件，或点击“新局重置”；撤销不会解除 PAUSED。
- 只有新局重置才可开始新的 PRE_PLAY 观察。这样避免在漏掉一手牌后继续显示貌似正常但实际错误的剩余数。

## 12. 持久化与异常恢复

- 保存当前牌局事件日志和最近可靠状态。
- 保存固定规则版本、ROI 配置和模板版本。
- App 意外退出后，重放事件恢复横条。
- 恢复后执行全部不变量校验。
- 保存最近若干秒关键 ROI 帧，用于 RETRY，不保存整局完整屏幕。
- 用户点击撤销，只撤销最后一次已接受的 OUTSIDE 扣减事件。
- 新局重置后重新识别自己实际持牌，不沿用上一局快照。
- 已接受事件先原子持久化，再归约状态并刷新横条；崩溃恢复以事件日志为准。

### 12.1 牌局生命周期与新局门禁

牌局状态只有：

    PRE_PLAY → ACTIVE → PAUSED → CLOSED

规则：

- 首次进入 PRE_PLAY：只观察发牌、贡还买牌和自己的候选手牌，不显示正式外面剩余。
- 任何展示区首次出现正式出牌候选前，锁定 lastStablePrePlayHand，随后进入 ACTIVE。
- ACTIVE 中桌面清空、旧牌组消失、过牌或等待动画，都**不是**新局证据，禁止清零。
- 只有“上一局已结束/结算”与“新一局发牌或开局标记”两类独立证据同时成立，才自动关闭旧会话并创建新会话。
- 证据不完整时进入 PAUSED，保持旧日志和横条，不静默重置。
- 用户点击横条的“新局重置”立即创建新会话，不弹确认；该操作只允许在用户明确认定已开新局时使用。

恢复规则：

- App 或 MediaProjection 中断后，存在已保存会话则重放并恢复为 PAUSED，等待重新观察，不从中途画面重新构建 SelfLockedHand。
- 没有已保存会话而画面已处于正式出牌阶段，显示红色“需从新局开始观察”，不猜测基线。
- 每个会话独立保存规则版本、六区标定版本、模板版本和事件日志；新局不得复用旧局的 SelfLockedHand。

### 12.2 本地数据边界

- 首版不联网、不使用账号、不上传画面、事件或模板。
- 不申请 INTERNET 权限。
- 持久化仅保存事件日志、规则/模板/六区标定版本和必要会话元数据。
- 短时 ROI 帧缓冲仅驻留内存，用于当前 RETRY；不保存整局录像，也不把完整屏幕帧写入磁盘。
- PAUSE 后如需调试，只显示原因码和事件元数据；不新增录像导出功能。

## 13. Android 技术路线

- MediaProjection 获取游戏画面。
- Foreground Service 保持截屏会话。
- `TYPE_APPLICATION_OVERLAY` 显示单横条。
- 低成本持续监测 ROI；只在变化时启动完整识别。
- 完整帧格式、行填充、采样率以目标手机真机验证为准。
- 不提前承诺 RGB565 或“VirtualDisplay 直接输出 ROI”。

### 13.1 首版目标设备

| 项目 | 结论 |
|---|---|
| 手机 | 华为 Mate 60 |
| 系统 | HarmonyOS 4.2.0 |
| 游戏方向 | 横屏 |
| 首版适配范围 | 仅此手机与该系统版本 |
| 提供录屏样本 | H.264，1280×578，约 59.98fps，时长 22.09 秒 |

录屏样本的 1280×578 只作为当前视觉标定基线；G1 必须实测该设备上 MediaProjection 的实际画布尺寸、裁切、帧率和是否包含浮窗。

编码前必须验证：

1. 目标游戏能否被 MediaProjection 正常截取。
2. 游戏是否主动隐藏其他 App 浮窗。
3. 横屏方向、刘海、安全区和坐标缩放。
4. 单横条能否穿透触控且不挡关键区域。
5. 持续截屏的耗电、内存和温度。
6. MediaProjection 画面是否包含自身浮窗。

浮窗与识别 ROI 必须隔离：

- 横条不得覆盖中央牌区、自己手牌区、行动高亮区。
- 拖动后若进入识别 ROI，自动吸附到安全区或拒绝该位置。
- 调试面板同样不得进入识别 ROI。
- 若截图包含自身浮窗，视觉层必须使用固定排除区域，禁止把浮窗变化当游戏事件。

## 15. 验收指标

### 15.1 正确性

| 指标 | 暂定门槛 |

- 从外面牌面稳定到横条更新，P95 ≤ 500ms。

- 屏幕只有一条统计横条。
- 不遮挡中央牌面和自己 Rank 角标。
- 横条外区域触控正常。
- 一局运行中无明显漂移或闪烁。

## 18. 风险清单

| 优先级 | 风险 | 对策 |
|---|---|---|
| P0 | 无法判断贡牌/买牌何时结束 | `lastStablePrePlayHand` + 第一项正式动作边界 |
| P0 | 游戏不显示手牌总数，初始手牌可能漏识别 | 牌位锚点与可见牌边缘双计数 + 多帧一致性；不一致即 PAUSE |
| P0 | SELF 被误判成 OUTSIDE，造成重复扣减 | 自身展示区 + 稳定牌组；禁止“非 SELF 即 OUTSIDE”反证推断 |
| P0 | OUTSIDE 被误判成 SELF，造成漏扣 | 对手展示区 + 稳定牌组；未知区域不扣；短时环形帧缓冲 |

| P0 | 横条覆盖顶部展示区，或截图含横条导致误识别 | 六区标定后锁定横条矩形；截图内固定排除横条区 |

| P0 | 中途重启后用当前手牌重建基线 | 重放旧事件；无会话时只允许从新局 PRE_PLAY 初始化 |
| P0 | PAUSE 后继续自动记导致错误扩大 | PAUSE 设为本局终态；只允许新局重置 |
| P0 | 游戏禁止截屏或浮窗 | G1 真机探针先行 |
| P0 | 出牌变化完全漏检后仍显示正常 | ObservationCompletenessGuard + actionEpoch 闭环 |
| P1 | 动画导致重复事件 | 六区展示状态机 |
| P1 | 连续相同牌面 | 事件重新布防，不以 Hash 作为唯一边界 |
| P1 | 模板分数不稳定 | 真实录屏标定，多帧融合 |
| P1 | 计数开始后再次发生牌权交换 | 首版立即 PAUSE，不替换基线 |

- OUTSIDE 必须有对手出牌证据与中央牌面的时空绑定；明确禁止“没看见自己控件”即判 OUTSIDE。
- `ActionBoundaryDetector` 增加短时前后帧环形缓冲，以处理提示和中央牌面不同步。

## 24. v5.3 → v5.4 六区候选路线

- 加密逐帧审查显示：自己的公开牌稳定在底部自身区，右下对手公开牌稳定在其头像附近；上方座位也有独立牌组。
- 出牌观察改为六个固定展示区；展示区只在运行时用于 SELF/OUTSIDE 二分类，不写入玩家身份或历史。
- “中央牌区”不再是唯一入口；牌组落在未知区域时不猜测，直接 RETRY 或 PAUSE。
- 新增语义门禁：只有 FORMAL_PLAY + OUTSIDE 才能更新 OutsidePlayed；交贡、买牌、过牌、开点及未知展示一律不扣。
- 六区路线尚未冻结，G3/G4 需用完整录屏逐帧验证覆盖率与“开点”语义。

## 25. v5.4 → v5.5 开点语义确认

- 用户确认：“开点”会让显示的牌真正离开出牌者手牌。
- 开点归为 FORMAL_PLAY；牌组稳定于对手展示区时，计入 OutsidePlayed。
- “开点语义”待确认项关闭；六区覆盖率和其他未知特殊展示仍为 G3/G4 门禁。

## 26. v5.5 → v5.6 六区标定规则

- 六区采用归一化画布坐标和头像向桌内的相对展示区，禁止写死单机像素。
- 每区定义不重叠的接受安全区；跨区、区外、被横条遮挡的牌组一律 UNKNOWN。
- UNKNOWN 不猜测，RETRY 后仍不唯一则 PAUSE。
- 区名只存在于瞬时视觉层；事件日志仍只保存 SELF / OUTSIDE。
- 左上横条的最终尺寸和偏移从属于六区安全边界，不能以 UI 需求侵占展示区。

## 27. v5.6 → v5.7 生命周期门禁

- 六区状态机按区独立运行，旧牌组可留在原区；另一展示区的新牌组仍可形成新事件。
- 桌面清空、过牌、等待动画不得触发新局。
- 自动新局需要“上一局结束/结算”与“新一局发牌或开局标记”两类独立证据。
- 中途重启不允许从当前手牌重建基线；恢复旧会话为 PAUSED，无会话则要求从新局开始观察。

## 28. v5.7 → v5.8 PAUSE 终态

- PAUSE 不提供继续本局自动记；漏掉或误判关键事件后继续会让错误静默扩大。
- PAUSE 后只保留收起、调试、撤销最后一次已接受事件和新局重置。
- 撤销用于审计，不恢复自动记；只有新局重置进入新的 PRE_PLAY。

## 29. v5.8 → v5.9 运行边界确认

- 首版只适配华为 Mate 60 / HarmonyOS 4.2.0。
- 全部数据本地处理：不联网、不上传、不保存整局录像；短时 ROI 缓冲仅在内存。
- 正式阶段可扣库存的动作已收敛为普通出牌和开点；用户确认没有其他会离手的特殊动作。
- 提供录屏样本为 1280×578、约 60fps；其与 MediaProjection 实测输出的差异仍是 G1 门禁。
